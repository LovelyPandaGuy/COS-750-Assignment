# 1a · Screen flow — how the screens connect

Source: `../source/AVL Primer Wireframes.dc.html#1a` (diagram, 2760×600). Not a screen; it is the route map.

## Nodes (boxes, exact text)

- **1 · Start**: purpose · start/resume · privacy · reset → [1b](1b.md)
- **2 · Diagnostic**: ~6 Qs, 1 per screen, skippable → [1c](1c.md)
- **2b · Diagnostic result**: secure / needs review per sub-skill → [1d](1d.md)
- **U0 primer**: conditional (dashed box)
- **3 · Unit hub**: ProgressMap · guided path (default) · reorder activities → [1e](1e.md)
- **6 · Sandbox**: insert 1–99 · rebalancing on/off → [1n](1n.md)
- Group box: **EACH UNIT U0–U5 · default order, student may reorder**
  - **4 · Explore**: predict → watch / do → [1f](1f.md), [1g](1g.md), [1h](1h.md)
  - **4 · Worked ex.**: step through → [1f](1f.md) (same layout, 1p assumption 4)
  - **5 · Check**: correct → next item → [1i](1i.md), [1j](1j.md), [1m](1m.md)
  - **Scaffold**: hint → worked → guided → [1j](1j.md), [1k](1k.md)
  - **Retry cap (3)**: → add to lecture Qs → [1l](1l.md)
- **7 · Readiness summary**: per-outcome status · lecture Qs · print / save → [1o](1o.md)

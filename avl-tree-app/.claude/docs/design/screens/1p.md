# 1p · Assumptions & open questions

Source: `../source/AVL Primer Wireframes.dc.html#1p`. Not a screen.

## Assumptions I made (word for word)

1. Balance factor = height(left) − height(right); a leaf has height 1, empty subtree height 0.
2. Diagnostic has ~6 items (1–2 per sub-skill) and shows no per-item right/wrong; skip = “needs review”.
3. Any “needs review” recommends U0, but the student can skip it. Units are never hard-locked.
4. The worked example uses the same layout as Explore (1f) with no predict prompt and fuller step text.
5. Only Check answers feed readiness. Explore / Do-it-yourself / Sandbox are never recorded as performance.
6. Readiness rule (draft): secure = correct on first or second attempt for all items of the outcome; developing = mixed; not yet = retry cap hit or unattempted.
7. “Trace an insert” uses constrained edits (place key, rotate) rather than freehand drawing.
8. Read-aloud uses the browser's built-in speech; a global “Aa” menu holds text size, read-aloud voice/speed and reduced motion.
9. Tablet (≥1024 wide): right column stacks under the tree; same components.

## Questions before moving on (word for word)

1. Is “left − right” the convention your lecturer uses? It drives every label and the misconception feedback.
2. Should the diagnostic reveal answers at the end, or only the sub-skill status?
3. Do you want deletion covered anywhere (U5 or Sandbox), or insert only?
4. Does the retry cap apply per question (as drawn) or per check?
5. Should lecture questions be exportable in a format the lecturer collects (e.g. copy to a forum), or private print only?
6. Is the Sandbox reachable from the start, or only after U1 (where the chain idea is introduced)?
7. Pseudocode: generic (as drawn) or the language your course uses (Java / Python)?
8. Do you want 2–3 alternative layouts for the core screen (e.g. pseudocode under the tree, or tabs) before high-fi?
